# WarehouseOS — адресный склад запчастей

Система управления центральным складом запчастей: адресное хранение, документы, инвентаризация,
отчёты, дашборды, роли и администрирование. Стек тот же, что у jac-yard: Node.js + Express,
SQLite (better-sqlite3), вход по cookie-сессиям. Сервис отдельный, база своя, релизы независимые.

## Разделы

| Раздел | Что делает |
|---|---|
| **Дашборды** | Сводка в реальном времени. Конструктор: 25 метрик, вид (плитка, линия, столбцы, полосы, таблица), период, зона, ширина, порядок перетаскиванием. Общие и личные дашборды |
| **Карта склада** | План зон, фасады стеллажей, поиск по артикулу и адресу, приёмка и отбор с маршрутом на схеме, пересчёт, перемещение, блокировка |
| **Поставки** | Документы приёмки: создание в вебе, вставка строк из Excel, переход к размещению |
| **Заказы дилеров** | Создание, контроль сроков, сборка по маршруту, закрытие с недостачей |
| **Каталог** | Артикулы, зона хранения, вместимость ячейки, минимальный остаток, загрузка из Excel |
| **Инвентаризация** | Задания по зонам или рядам, подсчёт (в том числе слепой), закрытие с записью факта |
| **Отчёты** | 9 отчётов: остатки по адресам и артикулам, заполненность, движение, поставки, заказы, производительность сотрудников, ABC-анализ, расхождения инвентаризации. Выгрузка в Excel |
| **Пользователи** | Создание, роли, отключение, сброс пароля, завершение сеансов |
| **Роли и права** | 4 встроенные роли и свои роли из 19 прав |
| **Топология** | Зоны, ряды, стеллажи, ярусы, ячейки — правка в вебе с предпросмотром схемы |
| **Настройки** | Название склада, фирменный стиль (подпись, логотип, фото здания), частота обновления, резервная копия базы |
| **Дилеры** | Справочник дилеров из Carsale «Запчасти → Справочники → Дилеры», проверяется по расписанию; карточка с историей заказов |
| **Интеграция Carsale** | Каталог, остатки центрального склада и дилеры из Carsale по расписанию, сверка «Carsale ↔ ячейки», поставка на неразмещённое |
| **Журнал аудита** | Входы, изменения пользователей, ролей, настроек, каталога, топологии |

## Роли

| Роль | Код | Что может |
|---|---|---|
| Администратор | `admin` | всё |
| Начальник склада | `manager` | все складские операции, документы, каталог, инвентаризация, отчёты, общие дашборды, аудит |
| Кладовщик | `storekeeper` | размещение, отбор, перемещение, пересчёт, подсчёт инвентаризации |
| Наблюдатель | `viewer` | только просмотр: карта, дашборды, отчёты |

Меню и кнопки показываются по правам; сервер проверяет права на каждом запросе. Выдать права,
которых нет у себя, нельзя. Последнего администратора отключить нельзя.

REST API рассчитан и на Android-клиент с офлайн-очередью, описание в [docs/API.md](docs/API.md).

## Требования

- Debian 11, 12 или 13
- Node.js 20 или новее:
  - Debian 13 — пакет из репозитория (`apt install nodejs npm`);
  - Debian 11/12 — установщик поставит Node.js 22 из NodeSource с ключом `--install-node`.
- Доступ к npm при установке (express и better-sqlite3).

## Установка через GitHub

На сервере Debian:

```sh
sudo apt install -y git
git clone git@github.com:tailscale654-glitch/parts-yard.git ~/parts-yard
cd ~/parts-yard
sudo sh install.sh                 # с демо-данными
```

Обновление после `git push` с рабочего компьютера:

```sh
cd ~/parts-yard && sudo sh update.sh
```

`update.sh` забирает код (`git pull`) и переустанавливает службу. База, пользователи
и настройки остаются; при первом запуске новой версии база обновляется сама
(в журнале службы: «База обновлена до версии …»). Демо-данные при обновлении не загружаются.

Для приватного репозитория нужен доступ с сервера: deploy key (SSH-ключ только на чтение,
GitHub → Settings → Deploy keys) и адрес вида `git@github.com:tailscale654-glitch/parts-yard.git`.

## Установка из архива

```sh
tar xzf parts-yard-node.tar.gz
cd parts-yard
sudo ./install.sh                  # с демо-данными
sudo ./install.sh --no-demo        # пустой склад
sudo ./install.sh --install-node   # если Node.js нет или он старше 20
```

Установщик выполнит следующее:

- создаст пользователя системы `partsyard`;
- поставит зависимости в `/opt/parts-yard`;
- запустит службу `parts-yard` на порту **8090**;
- создаст администратора `admin` и **один раз** покажет его пароль.

Обновление: распакуйте новую версию и снова запустите `sudo ./install.sh`.
База, пользователи и настройки сохраняются.

Если `npm ci` не может скачать готовый модуль better-sqlite3, поставьте компилятор
(`sudo apt install build-essential python3`) и повторите установку.

## Пользователи

Удобнее всего — в разделе «Пользователи». Из командной строки:

```sh
sudo parts-yard user-add petrova --name "Петрова Елена"      # кладовщик, пароль сгенерируется
sudo parts-yard user-add ivanov --role manager --password 'Склад2026'
sudo parts-yard user-add admin --role admin                  # новый пароль администратору
sudo parts-yard user-del petrova                             # отключить и выкинуть из всех сессий
sudo parts-yard user-list
sudo parts-yard role-list
```

Повторный `user-add` для существующего логина меняет пароль и роль и завершает его сессии.
Так же восстанавливается доступ, если пароль администратора забыт.

## Где что лежит

| Путь | Что это |
|---|---|
| `/etc/default/parts-yard` | порт, демо-режим, параметры сессий и прокси |
| `/etc/parts-yard/layout.json` | начальная топология; после правки в разделе «Топология» хранится в базе |
| `/var/lib/parts-yard/warehouse.db` | база SQLite (WAL) |
| `/opt/parts-yard/` | программа, примеры CSV, docs/API.md |

После изменения `/etc/default/parts-yard`: `sudo systemctl restart parts-yard`.
Журнал службы: `journalctl -u parts-yard -f`.

## Данные

Каталог, поставки и заказы проще загружать в вебе: кнопки «Загрузить из Excel» и «Вставить из Excel».
Для обмена с учётной системой есть командная строка. CSV в UTF-8 (из Excel — «CSV UTF-8»),
разделитель `;`, `,` или табуляция, заголовок необязателен. Образцы в `/opt/parts-yard/examples/`.
Резервную копию можно скачать и в разделе «Настройки».

```sh
sudo parts-yard import-skus catalog.csv                          # артикул;наименование;зона;вместимость[;минимум]
sudo parts-yard import-receipt receipt.csv --doc ПТ-10413 --gate 2   # артикул;количество
sudo parts-yard import-order order.csv --number ЗК-24130 --dealer "Дилерский центр «Юг»" --due 16:00
sudo parts-yard export-stock /root/остатки.csv
sudo parts-yard backup /root/warehouse-$(date +%F).db             # копия на ходу, без остановки
```

### Переход с демо на реальные данные

```sh
sudo sed -i 's/^WMS_DEMO=.*/WMS_DEMO=0/' /etc/default/parts-yard
sudo systemctl stop parts-yard
sudo cp /var/lib/parts-yard/warehouse.db /root/warehouse-demo.db
sudo rm /var/lib/parts-yard/warehouse.db*
sudo parts-yard init
sudo parts-yard user-add admin --role admin
sudo parts-yard import-skus catalog.csv
sudo systemctl start parts-yard
```

Свой склад (зоны, ряды, ярусы) настраивается после входа в разделе «Топология».

## Интеграция с Carsale

WarehouseOS сам входит в Carsale (`crm.carsale.uz`, тот же API, что у app.carsale.uz) и по расписанию
забирает каталог запчастей и остатки центрального склада. В Carsale ничего не меняется — только чтение.
Заказы клиентов и персональные данные не загружаются.

Настройка — один раз на сервере. Пароль хранится только в `/etc/default/parts-yard` (доступ только root)
и никогда не попадает в браузер, базу или git:

```sh
sudo nano /etc/default/parts-yard
#   CARSALE_LOGIN=логин
#   CARSALE_PASSWORD='пароль'        # в одинарных кавычках, если есть пробелы или $ " \
sudo systemctl restart parts-yard
sudo parts-yard carsale-sync         # первая синхронизация с выводом результата
sudo parts-yard carsale-status       # история синхронизаций
sudo parts-yard dealer-list          # справочник дилеров
```

Для синхронизации лучше завести в Carsale отдельного пользователя с правом только на просмотр запчастей.

Что приходит из Carsale:

| В Carsale | В WarehouseOS |
|---|---|
| Справочник: код, название, тип (A, B, C, D, TOOLS), цена, единица, модель, стеллаж | Каталог. Тип → зона склада (настраивается), вместимость ячейки — значение по умолчанию |
| Остатки со статусом «На складе» и «Бронь для заказа» | Колонка «В Carsale» в каталоге и отчёт «Сверка с Carsale» |
| «Запчасти → Справочники → Дилеры»: код, название, регион, адрес, телефон, ИНН, активность | Раздел «Дилеры» и выбор дилера в заказе |

Дилеры в WarehouseOS — только из этого справочника Carsale, своих дилеров нет. Каждая синхронизация
делает справочник точной копией: новые добавляются, изменённые обновляются (переименование доходит и до заказов),
удалённые в Carsale удаляются и здесь — у их заказов остаётся имя дилера. Неактивные в Carsale дилеры
не предлагаются в новых заказах. Если Carsale вернул пустой список, справочник не трогается.
Все изменения — в «Журнале аудита». Логины, пароли и ключи интеграций дилеров, которые Carsale отдаёт
в том же ответе, не сохраняются. Загрузку дилеров можно выключить в разделе «Интеграция Carsale».

Адреса ячеек ведёт WarehouseOS. Если по Carsale на складе больше, чем разложено по ячейкам,
в разделе «Интеграция Carsale» кнопка «Поставка на неразмещённое» создаёт поставку на разницу —
дальше обычная приёмка с подбором адресов на карте. Зону артикула синхронизация не меняет,
если он уже лежит в ячейках или зону поменяли вручную в каталоге.

Частота, статусы, склады Carsale и соответствие типов зонам — в разделе «Интеграция Carsale».

## Ячейки склада из Excel и запись в Carsale

Раздел «Администрирование → Ячейки склада»:

1. **Файл с ячейками** (.xlsx или CSV, столбцы «Артикул», «Номенклатура», «Ячейка»). Адреса вида
   `A-08-01-02` (зона-стеллаж-ярус-ячейка); `B-01-03-02\03` — ячейки 02 и 03; `A-016-…` — лишние нули убираются;
   `D/Z-…` — зона DZ. По файлу строится топология, а у артикулов появляются закреплённые ячейки: туда система
   размещает товар в первую очередь. Строки с ошибкой показываются и не загружаются.
   В консоли то же самое: `sudo parts-yard import-cells ячейки.xlsx [--clear-cells]`.
2. **Записать в Carsale.** Сначала план без изменений, потом запись по кнопке: недостающие ячейки создаются
   в «Справочнике стеллажей/ячеек» выбранного склада, в карточке запчасти ставится первая закреплённая ячейка,
   по желанию остатки на складе переносятся в неё. Пользователю Carsale из `/etc/default/parts-yard` для этого
   нужны права на справочники запчастей. Всё записывается в журнал аудита.

## HTTPS: адрес без порта

Скрипт `ssl-setup.sh` ставит nginx, кладёт сертификат, открывает систему по `https://<домен>`
(с `http://` перенаправляет на https) и закрывает прямой доступ к порту 8090.

```bash
# с компьютера Windows скопировать файлы сертификата на сервер (в домашнюю папку)
scp certificate.crt ca-bundle.crt private.key user1@<IP сервера>:~/

# на сервере
cd ~/parts-yard && git pull
sudo sh ssl-setup.sh sklad.jacmotors.uz ~/certificate.crt ~/private.key ~/ca-bundle.crt
rm -f ~/private.key                       # копия ключа больше не нужна
```

Скрипт проверяет, что ключ подходит к сертификату, имя домена покрывается сертификатом и срок не истёк.
Ключ хранится в `/etc/ssl/parts-yard/privkey.pem` (доступ только root), в git он не попадает.
Если nginx не примет настройки, скрипт ничего не меняет.

- Сертификат выдаётся на имя, поэтому нужна DNS-запись `sklad.jacmotors.uz → IP сервера`
  (во внутреннем DNS компании или у регистратора домена). По IP браузер покажет предупреждение.
- Продление: та же команда с новыми файлами.
- Вернуть как было (`http://IP:8090`): `sudo sh ssl-setup.sh --off`.
- Если на сервере уже есть nginx с другими сайтами (например, jac-yard), они не затрагиваются.

## Как подбираются адреса

- **Размещение.** Сначала дозаполняются ячейки с тем же артикулом в его зоне, затем занимаются
  свободные: ближе к центральному проезду и воротам. В зонах с `"prefer": "middle"` первыми идут
  средние ярусы, в остальных нижние. Если места не хватает, остаток остаётся в строке поставки.
- **Отбор.** Минимум точек: строка заказа по возможности берётся из одной ячейки, а из подходящих
  выбирается наименее полная, чтобы освобождать место. Точки упорядочены по проходам, маршрут
  начинается и заканчивается в зоне отгрузки.

## Разработка

```sh
npm install
WMS_DEMO=1 node cli.js init --demo
node cli.js user-add admin --role admin --password admin123
WMS_DEMO=1 WMS_DEV=1 npm start  # http://localhost:8090, статика без кэша
npm test                        # 28 тестов: роли, остатки, opId, документы, отчёты, инвентаризация, топология, Carsale (на макете API)
```

Структура:

```
src/        сервер: app.js (маршруты склада), api-docs.js, api-insights.js, api-admin.js,
            warehouse.js (логика адресов), metrics.js, reports.js, inventory.js, perms.js, db.js (миграции)
public/     веб-интерфейс без сборки: js/app.js (оболочка), js/views/*.js (разделы), css/app.css
test/       тесты API (node --test)
```

## Удаление

```sh
sudo ./uninstall.sh
```

База и настройки остаются на диске.
